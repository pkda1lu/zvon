## Как сообщить об ошибке

Если вы столкнулись с проблемой, пожалуйста, создайте **Issue** в нашем репозитории. Чтобы мы могли быстрее помочь, укажите:
* **Описание**: Краткое и понятное описание проблемы.
* **Шаги для воспроизведения**: Список действий, которые приводят к ошибке.
* **Окружение**: Ваша ОС, версия Node.js и тип клиента (Браузер или Electron).
* **Скриншоты или логи**: Если ошибка визуальная или связана с вылетом приложения.

## Предложение новых функций

Мы стремимся сделать Zvon максимально удобным. Если у вас есть идея:
1. Проверьте существующие Issue, чтобы избежать дубликатов.
2. Создайте новый Issue с описанием функционала и его пользы для пользователей.

## Процесс разработки (Workflow)

Мы используем стандартную модель GitHub Flow:

1. **Форкните репозиторий** и создайте локальную копию.
2. **Создайте ветку** от `main` с понятным названием:
   ```bash
   git checkout -b feature/your-feature-name
   # или
   git checkout -b bugfix/fix-some-issue
   ```
3. **Установите зависимости**:
   ```bash
   cd server && npm install
   cd ../client && npm install
   ```
4. **Внесите изменения**. Постарайтесь разбивать логику на понятные коммиты.
5. **Проверьте работу**: Убедитесь, что сервер запускается, а клиент корректно отображает изменения.
6. **Закоммитьте изменения**:
   ```bash
   git commit -m "feat: описание новой функции" 
   ```
   *Рекомендуем использовать [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/).*
7. **Отправьте изменения** в свой форк и создайте **Pull Request**.

## Стандарты кодирования

Для поддержания чистоты кода мы просим придерживаться следующих правил:

* **React**: Используйте функциональные компоненты и хуки. Избегайте лишних перерендеров.
* **Стили**: Мы используем **Vanilla CSS** с CSS-переменными. Не используйте сторонние UI-библиотеки без предварительного обсуждения.
* **TypeScript**: Начинайте внедрять типы там, где это критически важно для надежности.
* **Node.js**: Придерживайтесь асинхронного подхода (`async/await`) и обрабатывайте ошибки в контроллерах.

## Структура проекта

* `/client`: Исходный код интерфейса (React, Vite).
* `/server`: Логика бэкенда (Express, Socket.io, Mongoose).
* `/native-audio`: Нативные модули для захвата звука (C++).
* `/bot-example`: Пример реализации бота для платформы.
