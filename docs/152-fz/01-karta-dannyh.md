# Карта персональных данных Zvon и разрывы по 152-ФЗ

Документ описывает, какие персональные данные (ПД) обрабатывает Zvon, где они
хранятся, кому передаются и чего не хватает для соответствия Федеральному закону
№ 152-ФЗ «О персональных данных».

Составлено по исходному коду. Все утверждения о том, что данные собираются или
куда-то уходят, проверены по файлам — ссылки приведены. Утверждения о правовой
квалификации требуют проверки юристом: я описываю фактическую обработку, а не даю
юридическое заключение.

Дата составления: 14.08.2026.

---

## 1. Роль организации

Zvon — **оператор персональных данных** (ст. 3 п. 2): определяет цели и состав
обрабатываемых данных, организует обработку.

Обработка ведётся с использованием средств автоматизации.

---

## 2. Какие ПД обрабатываются

### 2.1 Учётная запись — `server/models/User.js`

| Данные | Поле | Обязательность |
|---|---|---|
| Адрес электронной почты | `email` | обязательно при регистрации |
| Логин | `username` | обязательно |
| Отображаемое имя | `displayName` | по желанию |
| Пароль | `password` | хранится в виде хеша (bcrypt) |
| Фото профиля, баннер | `avatar`, `banner` | по желанию |
| Сведения о себе | `bio` | по желанию |
| Статус | `status`, `statusPreference` | автоматически |
| **Текущая активность** | `activity` | автоматически, если включено |
| Заметки о других пользователях | `notes` | по желанию |
| Роль, блокировки | `role`, `isBanned`, `banReason`, `banExpires` | служебное |

Отдельно отмечу `activity`: приложение определяет, **какую игру или программу
запустил пользователь**, — это делает опросчик в главном процессе Electron
(`client/public/electron.js`). Данные о поведении и предпочтениях человека,
собираемые постоянно и в фоне. Такое требует прозрачного описания в политике и
явно управляемого отключения.

### 2.2 Сессии и устройства — `server/models/Session.js`

| Данные | Поле |
|---|---|
| **IP-адрес** | `ip` |
| **Страна, город** | `country`, `countryCode`, `city` |
| User-Agent, браузер, ОС | `userAgent`, `browser`, `os` |
| Тип и имя устройства | `deviceType`, `deviceName` |
| Идентификатор устройства | `deviceId` |
| Время создания и активности | `createdAt`, `lastActiveAt` |

Сессии удаляются автоматически по истечении срока (TTL-индекс на `expiresAt`) —
это уже реализовано и работает в пользу соблюдения принципа ограничения срока
хранения.

### 2.3 Содержимое сообщений — `Message`, `DirectMessage`

Личная переписка. Помимо 152-ФЗ здесь действует **тайна связи** (ст. 23
Конституции РФ), режим строже: доступ к содержимому переписки для сотрудников
должен быть исключён либо строго регламентирован и журналирован.

Отдельно: чаты модерации (`isModeration`) — переписка сотрудников с
пользователями по поводу нарушений.

### 2.4 Прочее

| Модель | Что содержит |
|---|---|
| `Report`, `ProblemReport` | жалобы: кто пожаловался, на кого, снимок содержимого |
| `AuditLog`, `GlobalAuditLog` | действия модерации |
| `StoreOrder`, `VpnOrder` | заказы и платежи |
| `PushSubscription` | endpoint push-сервиса, привязка к пользователю, User-Agent |
| `PendingRegistration` | данные незавершённой регистрации |
| `Friendship`, `Group`, `Server` | социальные связи — тоже ПД |

**Специальных категорий ПД (ст. 10) и биометрии (ст. 11) не обрабатывается.**
Фотография профиля биометрией не является, пока не используется для установления
личности; здесь такого использования нет.

## 3. Где хранится

По подтверждению владельца — сервер, база MongoDB и файловое хранилище загрузок
расположены **на территории Российской Федерации**.

Это закрывает требование ст. 18 ч. 5 (локализация баз данных граждан РФ) при
условии, что все перечисленные в разделе 4 передачи оформлены корректно.

Требует фиксации в документах: адрес размещения, реквизиты хостинг-провайдера,
договор с ним как с лицом, осуществляющим обработку по поручению (ст. 6 ч. 3).

## 4. Передача данных третьим лицам

Разбор по каждому сервису, как договаривались. «Уходит IP пользователя» означает,
что запрос идёт **напрямую из браузера или приложения пользователя**, — тогда
сервис получает его IP-адрес независимо от содержимого запроса.

| Сервис | Где вызывается | Что уходит | Юрисдикция | Оценка |
|---|---|---|---|---|
| **ip-api.com** | `server/utils/deviceInfo.js:97` | **IP-адрес пользователя** | США | Худший случай. IP отправляется на иностранный сервис ради определения города. Рекомендую заменить на локальную базу GeoIP — это снимает трансграничную передачу целиком |
| **smtp.gmail.com** | `server/utils/mail.js:4` (значение по умолчанию) | **Адрес почты, коды подтверждения** | США | Критично. Если `SMTP_HOST` не переопределён, вся почта идёт через Google. Нужен российский SMTP |
| **api.github.com** | `client/.../AppChangelogSettings.tsx:94` | IP пользователя | США | Запрос из браузера за списком релизов. Рекомендую проксировать через свой сервер |
| **youtube.com/embed** | `client/.../PresenceTile.tsx:87` | IP пользователя, cookies Google | США | iframe грузится напрямую. Смягчается доменом `youtube-nocookie.com`, но IP уходит в любом случае |
| **pay.crypt.bot** | `server/routes/store.js` | Данные заказа | вне РФ | Криптоплатежи. Требует отдельной правовой оценки — не только по 152-ФЗ |
| **api.giphy.com** | `server/routes/gifs.js:9` | Только поисковый запрос | США | **IP пользователя не уходит** — вызов идёт с сервера. Остаётся вопрос содержимого запроса |
| **steamgriddb.com** | `server/routes/…` | Название игры | США | Вызов серверный, ПД не передаются |
| **api.yookassa.ru** | `server/routes/store.js` | Платёжные данные | **РФ** | Российский оператор, трансграничной передачи нет |
| **LiveKit** | `LIVEKIT_URL` в окружении | **Голос и видео** | зависит от настройки | **Требует проверки.** Если это облако LiveKit, а не свой сервер в РФ, — трансграничная передача содержимого разговоров |
| **Apple / Google push** | Web Push | endpoint устройства, текст уведомления | США | Неустранимо: так работает Web Push. Требует описания в политике |

### Что с этим делать

Каждая передача за пределы РФ требует по **ст. 12** уведомления Роскомнадзора
**до начала** передачи, а по ст. 12 ч. 4 — оценки, относится ли страна к
обеспечивающим адекватную защиту. США к таким не относятся, что означает более
строгий режим.

Практический вывод: чем меньше остаётся иностранных сервисов, тем проще. Первые
два (ip-api и Gmail) устраняются заменой и должны быть устранены — они передают
самые чувствительные данные (IP и почту) без всякой необходимости.

## 6. Границы того, что решается кодом

Закрывается разработкой: согласие и его фиксация, выгрузка данных, удаление и
обезличивание, сроки хранения и автоочистка, журналирование доступа к ПД,
ограничение доступа сотрудников, устранение части иностранных сервисов.

**Не закрывается разработкой** и остаётся зоной ответственности организации:
уведомление РКН (об обработке и о трансграничной передаче), назначение
ответственного, модель угроз и определение уровня защищённости, аттестационные
мероприятия, договоры с обработчиками, регламент реагирования на инциденты,
обучение сотрудников, проверка черновиков документов юристом.

Соответствие 152-ФЗ — это состояние организации, а не свойство программы.
Программа может ему соответствовать или мешать; сама по себе она его не создаёт.
